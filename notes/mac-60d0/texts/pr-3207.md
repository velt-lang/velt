A sleep is a heap future that a promise holds. It lives in the timer block of the worker that first polled it, and only that worker touches the block. But a promise handed to another task is polled by that task from then on, and dropped by whoever holds it last, on that task's worker: a fresh task starts on any worker, a task that may move runs in its waker's slot, and an offer moves tasks. Such a poll wrote the sleep's waker while its worker's expiry read it, such a drop unlinked it from a list it was not in, and its expiry put it on the due list of a task of another worker. Main crashes on this in about one run in eight of the review's probes.

- **The rule**: a pending sleep is polled and dropped only on the worker whose block holds it (`S_HOME`), and expires for a task of that worker.
- **A poll or drop elsewhere** (sched_sleep_move.velt) writes nothing in the sleep. It leaves a request on the holding worker's list (`E_SLEEP_ASKS`, a stack any thread pushes on and its worker takes whole) and wakes that worker. The holder takes the sleep off its list (pending, due or fired), stores its state last (a new sleep again, or a seen one when it had fired) and wakes the asking waker; the task's next poll registers it in the block of the worker it runs on, as a first poll does. A dropped one is freed by the holder.
- **Which task polls** is the task the worker is polling, not what the promise's waker or context says (those name the task that owns the promise, also when another task awaiting it polls it). The task that polled a sleep into its block is anchored there with it, so its polls take no other path; another task's poll on the same worker anchors that task and makes it the sleep's owner for carries.
- **In transit**: a sleep is its holder's until that last store. Requests under way are counted in the sleep (`S_ASKS`): a drop meanwhile is a request itself, and the sleep is freed by whoever ends the last one, so no request names freed memory in any serving order. A request that finds another worker holding the sleep (its task was offered with it) goes on to that worker; one that finds it carried by an offered task waits for that task's next poll.
- **Serving**: before the worker's timer look and before it parks (checked again with its park word up, as its inbox), and every I/O tick while it is busy. A worker with requests counts as busy for the program's end, so a counted exit finds every list empty and every waker given back.
- **The rule as a check**: in a counted run (`VELT_RC_STATS`, as the tests run) a sleep that expires for a task of another worker, or is dropped off its worker, is an `ICE:`.

The cost on the common path is one more word per sleep, a read of the worker on a repoll of a pending sleep, and two loads in the worker's park.
