#131 DESIGN (from reading the code on main 8061c8631; nothing built or run yet, so 'inferred' items are marked). The owner's design works for the issue's program. Four findings need your yes/no before code (A, B, the handed-over wake) or measurement (C).

THE EXAMPLE, traced: task K (T_REFS 2: executor + handle; `void` drops the handle -> 1). `new Promise((resolve) => {})` becomes node N1 on K (bind: T_REFS 2, N_REFS 2, T_LOCALS 1); its run waits on `Promise.race([])`, registering nothing. The root awaits N1: pollNode adopts it, it stays pending with N_REFS 2 -> `lost.ownerOnly` (no awaiter stored). So K: T_REFS = 1 + T_LOCALS, idle, join word 0. A cycle K -> root frame -> N1 -> K. #3175 frees nothing here (N1 is not DETACHED). The 7 blocks (breakdown inferred): K, N1, the promise slot, its latch, the outcome buffer, the race's array and its join.

THE LIST: link in `ownerOnly` through N_NEXT (next) + N_TAKEN_NEXT (prev), both unused while N_REFS is 2 (a wake or a place on the woken stack is a reference). A node flag LISTED; task words T_LOST (head) and T_LISTED (count) added to the task block (16 bytes a task, no store at spawn: read only under a task flag LOST set at the first link). The list must be doubly linked and unlinked when a listed node FINISHES (inner nodes finish first, and a finished node is freed soon after, so a stale entry would dangle; a list reference would break every '=== 2' test). The unlink costs unlisted nodes nothing: `tr.finished` already tests a flag mask, widened to HANDED_OVER | LISTED, then out of line.

THE TEST, in runEnd before the CAS to idle (the task is this thread's until then): `flags & (LOST|ROOT|ROOT_DONE|T_CATCHES) == LOST && T_LISTED == T_LOCALS && T_REFS == T_LOCALS + 1` -> out of line: walk the list (each node: this task's, STARTED|LISTED, none of FINISHED/RUNNING/QUEUED/CATCHES/PANICKED/ADOPTED, N_REFS 2, or DETACHED with 1), then read T_STATE last (must still be RUNNING: a wake does its CAS before giving its reference back). A task that never listed a node pays one flag test on a word runEnd already loads. The count alone excludes sleeps, I/O waits, microtasks, a held handle and any waker clone: each is a reference.

THE FREE: not inline. The task is flagged CANCEL and queued once more; in that poll the root's state is DROPPED instead of polled (with E_CURRENT = the task, so each promise the frame owns goes through #3175's dropPending/giveUp, unlinking as it goes), ROOT_DONE is set, and the ordinary end of a poll does the rest (microtasks from dispose code, publish, finish: live count, executor's reference). If dispose code started new promises the task lives on as a root-done task until they end. Dispose hooks of what the frame held now run (as #3175): a docs-sync issue.

`main`'s root is excluded by the ROOT flag. A task holding ANOTHER parked task's handle (not awaiting it): freed, and its frame's drop of that handle frees the other (with B below). Two tasks awaiting each other's handles: out of scope (a cross-task cycle).

FINDINGS:
A. Chains: `await stuck()` where stuck awaits the dead promise is NOT reached by the counts. Adoption is one level deep (E_ADOPTING); the inner await stores a clone of the adopter's waker in the inner node (aw.awaitNode), so T_REFS is one too many, and at depth 3 the middle node has 3 references. Proposed: in pollNode's pending path take the owner-only exit also when adoption was refused only because one is under way (same conditions: not running/queued/catching, same task, N_REFS 2). ~3 lines in pollNode; same soundness argument as ownerOnly's. Without it only a root that awaits the dead promise DIRECTLY is freed. Yes/no?
B. A handle dropped AFTER the task parked is never seen (joinDropAs only decrements; nothing polls the task again). With several workers a helper can poll a `void spawn` to its park before the spawner drops the handle: rare, but a flaky leak check; and `const h = spawn(stuck()); ...; drop h` is never freed. Proposed: a J_PARKED bit set at the park when the test fails only by the handle's reference; joinDropAs seeing it (one test on a word it holds) goes out of line and wakes the task once, which parks again and passes. Yes/no?
C. `ownerOnly` is not rare: every suspended adopted await whose leaves use the adopter's waker takes it (e.g. `await delay()` over a sleep). Linking is then once per SUSPENDED awaited promise (an atomic or + four stores, and one out-of-line unlink at its finish); promises that never suspend under adoption pay nothing. To be measured on await_chain/timer_await* besides the spawn and fan-out rows.
D. The root's drop glue (T_DROP) is stored at spawn and never read today: freeing a task runs a root state's drop for the first time under this executor. To be tested with frames holding counted values.
Handed-over variant: with one worker #3175 already frees it. With several, the owner's drop on another thread only marks DETACHED (giveUp is for the task's thread); the list reaches it only if the node had been listed before the hand-over. A general fix would be: in that branch, wake the node once when it is unfinished with 2 references, so its task's next poll gives it up. Not in the owner's design: include it, or leave it and say so in the PR?
