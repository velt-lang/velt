A spawned task whose root waits on a promise nobody can settle, and that nothing can wake or join any more, is now freed with what its root holds. It used to stay parked until the program ended (7 blocks a task; `void spawn(async () => { await new Promise(() => {}) })` in a loop grew without bound).

How it is found (std/lang/hooks/sched_task_lost.velt): at the end of a poll, a task whose only references are the executor's and one per promise it drives, with every such promise counted as one only its owner can run, can never be polled again. Such a promise is counted (flag `LISTED`, set by the atomic step that ends the adoption's run, so the common path pays no extra read-modify-write) when an adoption poll leaves it with its owner's and its task's references only (sched_node_lost.velt `ownerOnly`); `nested` covers a promise left without an awaiter under an adoption already under way (a chain whose links were started before they were awaited). A counted promise stays owner-only until it finishes or is dropped, so the park reads only the count; with the block counters on (as the tests run), the promises are linked as well and the park walks them, so a promise that gained a waker is an `ICE:`. The task gets one last poll (flag `CANCEL`) that drops its root instead of polling it: what the root holds goes, its `[Symbol.dispose]` hooks run, and the task ends as one whose root finished. A task that parks like that with its join handle still held is marked (`J_PARKED`), and the handle's drop wakes it to be found.

Where Velt differs from Node on purpose: the dispose hooks of what a freed task held run (Node collects the same functions and runs nothing); the golden says so in its header.

Not covered (each documented in sched_task_lost.velt): a promise handed to another task and dropped there on another worker while suspended; a root waiting in a combinator; a waker dropped without a wake after the park; two tasks waiting for each other's join handles.

Tests: tests/golden/lang/task_parked_freed.velt (the program of #3126, roots holding counted values and disposables, chains of two and three, chains started before they were awaited, a dispose hook that starts a promise, a handle dropped after the park, and a control task that can still be woken), with no leaks, at 1, 4 and 8 workers and with the rescue.
